# Бизнес-процесс и сценарии

## Основной сценарий оформления заказа
1. Покупатель получает каталог.
2. Покупатель формирует запрос заказа.
3. Сервер валидирует структуру запроса.
4. Сервер проверяет ключ идемпотентности.
5. Сервер начинает транзакцию и блокирует/атомарно проверяет остатки.
6. Если все позиции доступны, сервер создаёт заказ и позиции, уменьшает остатки.
7. Сервер фиксирует транзакцию.
8. Сервер возвращает `201 Created` с идентификатором заказа.

## Альтернативные потоки
- Невалидный запрос: `400 VALIDATION_ERROR`, данные не изменяются.
- Товар не найден: `404 PRODUCT_NOT_FOUND`, данные не изменяются.
- Недостаточный остаток: `409 INSUFFICIENT_STOCK`, транзакция откатывается.
- Повтор ключа с тем же телом: возвращается исходный ответ без повторного списания.
- Повтор ключа с другим телом: `409 IDEMPOTENCY_KEY_REUSED`.

## Процесс отмены
1. Клиент вызывает отмену заказа.
2. Сервер проверяет существование заказа.
3. Сервер блокирует заказ и проверяет статус.
4. Если статус не `NEW`, возвращает `409 ORDER_NOT_CANCELLABLE`.
5. Если статус `NEW`, меняет статус на `CANCELLED` и восстанавливает остатки в одной транзакции.
6. Сервер возвращает актуальное состояние заказа.

## Исключительные ситуации и решения
| Ситуация | Ожидаемое поведение |
|---|---|
| Два клиента одновременно заказывают последний товар | Успешен только запрос, для которого хватает остатка; второй получает конфликт |
| Сбой до фиксации транзакции | Заказ и изменение остатка откатываются |
| Сбой после фиксации, но до ответа клиенту | Повтор с тем же `Idempotency-Key` возвращает исходный результат |
| Повторная отмена | Остаток не увеличивается повторно |
